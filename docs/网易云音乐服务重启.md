# 网易云音乐 API 服务手动重启说明

本文档记录 `ncm-api` 网易云音乐 API 服务失效时的排查和手动重启方法。

## 当前部署信息

- 服务器：`64.90.12.120`
- Docker 容器名：`ncm-api`
- 镜像：`moefurina/ncm-api:latest`
- 对外端口：`3051`
- 容器端口：`3000`
- 访问地址：`http://64.90.12.120:3051`

## 本次失效原因

排查时发现：

- `ncm-api` 容器状态为 `Exited (255)`。
- 容器退出时间为 `2026-06-26T07:52:53Z`。
- 服务器在 `2026-06-26 07:52 UTC` 左右发生过系统启动记录。
- 容器重启策略为 `no`。

因此，本次失效不是 AstrBot 插件问题，也不是网易云 API 接口变更；主要原因是服务器或 Docker 重启后，`ncm-api` 容器没有自动恢复。

## 手动重启

登录服务器后执行：

```bash
docker start ncm-api
```

如果容器已经在运行，但接口异常，可以执行：

```bash
docker restart ncm-api
```

## 查看服务状态

```bash
docker ps -a --filter name=ncm-api
```

正常情况下应看到 `ncm-api` 为 `Up ...`，并且端口映射包含：

```text
0.0.0.0:3051->3000/tcp
```

## 本机健康检查

在服务器上执行：

```bash
curl -sS -w '\nHTTP=%{http_code} TIME=%{time_total}\n' \
  'http://127.0.0.1:3051/login/status'
```

如果正常，应该返回 HTTP 200。

也可以测试搜索接口：

```bash
curl -sS -w '\nHTTP=%{http_code} TIME=%{time_total}\n' \
  'http://127.0.0.1:3051/search?keywords=test&limit=1&type=1'
```

## 外部访问检查

在 AstrBot 运行机器或自己的电脑上执行：

```bash
curl -sS -w '\nHTTP=%{http_code} TIME=%{time_total}\n' \
  'http://64.90.12.120:3051/login/status'
```

如果服务器本机访问正常、外部访问失败，再检查防火墙或 Docker `DOCKER-USER` 链。

## 查看日志

```bash
docker logs --tail 100 ncm-api
```

注意：该 API 可能会把请求参数完整写入日志。如果请求里带了网易云 Cookie，日志中可能出现账号 Cookie。不要把完整日志公开发送到群聊、Issue 或聊天窗口。

## 可选：设置自动重启

当前服务器已执行过该设置，`ncm-api` 的重启策略已经是 `unless-stopped`。

如果希望以后服务器重启后自动恢复，可以执行：

```bash
docker update --restart unless-stopped ncm-api
docker start ncm-api
```

设置后可用下面命令确认：

```bash
docker inspect ncm-api --format '{{json .HostConfig.RestartPolicy}}'
```

期望看到：

```json
{"Name":"unless-stopped","MaximumRetryCount":0}
```

## 容器不存在时的重新创建命令

只有在 `docker ps -a --filter name=ncm-api` 找不到容器时才需要重新创建：

```bash
docker run -d \
  --name ncm-api \
  --restart unless-stopped \
  -p 3051:3000 \
  moefurina/ncm-api:latest
```

创建后再次执行健康检查。
